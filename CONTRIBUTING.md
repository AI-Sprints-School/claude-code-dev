# Как здесь принято работать

Короткий свод правил проекта «Кошелёк». Читается за пять минут, экономит
пару часов на ревью.

## Ветки

Одна ветка — одна задача. Имя ветки: `fix/<что-чиним>` или
`feature/<что-добавляем>`, латиницей, через дефис.

```
fix/history-not-updated
feature/operations-csv-export
```

Ветка отходит от `main` и живёт не дольше нескольких дней.

## Коммиты

Сообщение в повелительном наклонении, первая строка до 72 символов,
без точки в конце. Тело коммита — зачем, а не что: «что» видно в диффе.

Один коммит — одно изменение по смыслу. Правка бага и переименование
переменных «заодно» — это два коммита, а лучше два PR.

## Pull request

В описании PR обязательны три вещи:

1. что было сломано или чего не хватало;
2. что изменено и почему именно так;
3. чем это проверено — команда теста и её результат.

PR без пункта 3 на ревью не берётся. «Проверил руками» — тоже
воспроизводимый пункт 3, если написано, что именно нажимали и что увидели.

## Тесты

Тесты бэкенда лежат в `app/backend/tests/`, и они разные.

Контрактные тесты API (`tests/contract_test.py`) — **разрушительные**:
фикстуры в `tests/conftest.py` пересоздают схему `public` и засевают
небольшой набор демо-аккаунтов. Направляйте их только на отдельную базу и никогда —
на ту, где лежат данные. Без флага `WALLET_ALLOW_DESTRUCTIVE_TESTS=1` они
пропускаются, чтобы случайный `pytest` ничего не снёс.

Остальные тесты базы не касаются вообще: тесты кэшбэка считают по списку
операций в памяти, поэтому идут обычным `pytest` — без Postgres, без флага
и без всякого риска для данных.

Правило простое: если вы чините дефект, в PR должен быть тест, который
краснеет на старом коде и зеленеет на новом. Тест, который зелёный
в обоих случаях, ничего не доказывает.

Тесты не удаляют и не помечают пропущенными, чтобы «прошла сборка».
Красный тест — это результат, а не помеха.

## Стиль

Python — 4 пробела, строки до 100 символов. JavaScript в `app/web/src/` —
без сборщиков, модулей и зависимостей: браузер должен получать ровно те
файлы, что лежат в репозитории.

Комментарий пишется про «почему», а не про «что». Комментариев про
очевидное в проекте нет, и заводить их не нужно.

## Секреты

В репозитории нет ни одного секрета, и это правило без исключений.
Строки подключения, пароли и ключи приходят только окружением, образец —
`app/backend/.env.example`. Файл `.env` закрыт в `.gitignore`.
