# Веб-клиент «Кошелёк»

Все экраны продукта: вход, главная, пополнение, списание, история,
ассистент и тарифы. API потребляется по контракту `../backend/spec/openapi.yaml`
— сам бэкенд живёт в соседней папке `../backend/`.

## Стек и почему такой

Статика: HTML, CSS и обычный JavaScript без модулей, сборщиков и
зависимостей. Ни npm, ни Node для работы не нужны, из инструментов —
только Python 3 из стандартной поставки.

Причина одна: в DevTools должно быть видно то же, что в репозитории.
В `Sources` лежат ровно те файлы, что в `src/`, во вкладке `Network` —
запросы вида `POST /api/wallet/topup` с телом `{"amount": 1000}`.

```
src/                       исходники
  index.html               единственная страница, дальше маршрутизация в JS
  styles.css               одна точка останова — 600 px
  config.js                адрес API
  js/
    version.js             версия сборки (подставляется при сборке)
    format.js              суммы «1 000,00 ₽» и даты
    messages.js            тексты сообщений продукта, дословно
    amount.js              берётся из variants/ при сборке
    api.js                 обёртка над fetch
    store.js               сессия, баланс, кеш истории
    ui.js                  всплывающие сообщения, точка останова, ошибки
    operations-view.js     таблица (десктоп) и карточки (мобильная)
    router.js              History API
    chrome.js              шапка с балансом и навигация
    app.js                 маршруты, охрана маршрутов, реакция на resize
    screens/               login, home, topup, withdraw, history,
                           assistant, tariffs
  variants/
    amount-1.4.0.js        валидация основной сборки
    amount-1.5.0.js        валидация регрессионной сборки
build.py                   сборка dist/ и dist/next/
serve.py                   локальный сервер: статика + прокси /api
```

`dist/` — продукт сборки, а не исходник: он закрыт в `.gitignore`
и пересобирается из `src/` одной командой.

## Как поднять локально

Нужен Python 3.9+ и запущенный бэкенд.

```bash
cd app/web
python3 build.py            # соберёт dist/ и dist/next/
python3 serve.py            # http://localhost:5173/
```

`serve.py` печатает три адреса:

- `http://localhost:5173/` — основная сборка 1.4.0;
- `http://localhost:5173/next/` — регрессионная сборка 1.5.0;
- адрес бэкенда, в который проксируется `/api`.

Вход — логином и паролем выданного аккаунта (`student-07` и пароль,
который печатает сид бэкенда). Регистрации в продукте нет.

## Как указать адрес бэкенда

Два разных механизма, для двух разных случаев.

**Локально (и в проде, если статику и API отдаёт один хост).** Клиент
ходит на относительный `/api`, а `serve.py` проксирует эти запросы в
бэкенд. Куда именно — задаёт `WALLET_BACKEND`:

```bash
WALLET_BACKEND=http://127.0.0.1:8000 python3 serve.py
```

Так запросы остаются same-origin: ни CORS, ни preflight-запросов в
`Network`, студент видит ровно те вызовы, которые делает приложение.

**Если API живёт на другом хосте.** Тогда адрес зашивается в сборку:

```bash
WALLET_API_BASE=https://wallet.example.org/api python3 build.py
```

Значение попадает в `dist/config.js`; бэкенду в этом случае нужен CORS.

## Как собрать обе версии

Обе собираются одной командой:

```bash
python3 build.py
```

| Сборка | Каталог | Маршруты | Отличие |
|---|---|---|---|
| 1.4.0 (140) | `dist/` | `/login`, `/topup`, … | основная сборка |
| 1.5.0 (150) | `dist/next/` | `/next/login`, `/next/topup`, … | другая клиентская валидация суммы |

Отличие между сборками — ровно три файла: `index.html` (пути к ресурсам),
`js/version.js` (строка версии) и `js/amount.js`, который берётся из
`src/variants/amount-<версия>.js`. Всё остальное побайтово одинаково,
проверяется так:

```bash
diff -rq dist/next dist --exclude=next
```

Обе сборки ходят в один бэкенд и одну базу.

## Переменные окружения

| Переменная | Где действует | По умолчанию | Что делает |
|---|---|---|---|
| `WALLET_API_BASE` | `build.py` | `/api` | базовый адрес API, зашивается в `dist/config.js` |
| `WALLET_BACKEND` | `serve.py` | `http://127.0.0.1:8000` | куда проксировать `/api` и куда перенаправлять `/sql`, `/docs` |
| `WALLET_PORT` | `serve.py` | `5173` | порт локального сервера |

## Развёртывание

`dist/` — обычная статика. От сервера нужны две вещи:

1. **Фолбэк на `index.html`** для маршрутов без файла, отдельно для каждой
   сборки: иначе `/topup` и `/next/topup` не откроются ни по прямой ссылке,
   ни по F5.
2. **Проксирование** `/api`, `/sql`, `/docs` и `/openapi.yaml` в бэкенд.

Для nginx:

```nginx
location /api/  { proxy_pass http://backend; }
location /sql   { proxy_pass http://backend; }
location /docs  { proxy_pass http://backend; }
location /next/ { alias /srv/wallet/dist/next/; try_files $uri /next/index.html; }
location /      { root  /srv/wallet/dist;      try_files $uri /index.html; }
```

Версия сборки видна в подвале каждой страницы — «Кошелёк 1.4.0 (сборка 140)».

## Что сюда не входит

`/sql` (SQL-консоль), `/docs` (Swagger UI) и вся логика AI-ассистента —
поверхности бэкенда. В веб-клиенте от них только ссылки в подвале и окно
чата на `/assistant`.
